# NegativeScan Studio app roadmap

Current app: **v1.13** · [App changelog](CHANGELOG.md) · [OFX roadmap](../ofx/ROADMAP.md) · [Versioning](VERSIONING.md)

## Implemented

- Camera and light control, film-base metering and leveling, HDR/trichrome capture and merge, crop, and hair/dust cleanup.
- v0.89 introduced a 5219/500T illuminant model. In v0.91 the app keeps only its Develop-preview calculator, without DCTL export or light changes.
- v0.90 introduced `nss.scan/1` TIFF scan provenance and preservation through image tools. v0.91 keeps tag 270 and the schema, but writes the accepted after-profile Light-page leveling result instead of a scene measurement. Both capture panels show the saved RGB/time and have a persisted default-on metadata switch.
- v0.91 removes the DCTL module, app template embedding, generators, export settings, and cross-module DCTL controls. The app has four modules and English-only built-in UI text.
- Camera chart calibration remains available under Camera & Light > Camera. Develop remains an independent in-app preview and positive-TIFF export tool.

## Next

1. Validate the four-module Windows UI and the complete X-T3/RGB Light Air workflow on real hardware. Check metering, ROI selection, leveling, Stop, scan presets, capture, and metadata accuracy.
2. Improve scan provenance coverage and missing-value diagnostics without inventing old scans' lamp/base values. Keep interoperability with the independent OFX plugin.
3. Validate the app's Develop-preview neutral-reference tools and model error using same-roll neutral steps. A transmission chart alone does not measure emulsion gamma.
4. Research measured scanner spectra, density crosstalk, and CIE daylight models. Keep capture-layer sensitivity distinct from scanner RGB axes.
5. Hikrobot monochrome (MV-CS240-90UM): v1.10 added black-level subtraction, a native mono HDR merge, frame averaging, a light settle check and an R/G/B movement check. v1.11 takes the noise model from the published sensor specs (12.1 ke-, 2.7 e-), removes the dark / flat tools and makes 0 / +2 / +3 / +5 EV HDR the default. Next: check on real film that the +5 EV frame's measured ratio and noise scale stay near nominal and that it adds no ghosting; time a real capture against the 3.6 s estimate; check that BlackLevel 32 is the real dark offset at long exposures; try the EX50 at f/2.8 (diffraction at f/4 limits luminance sharpness on this body). v1.12 adds non-blocking Hikrobot/Focus UI lifecycle, cached GDI preview painting with off-UI bitmap building, safe Mono Stop between steps, and narrow-panel text/clipping fixes without altering capture or image algorithms. v1.13 stabilizes Focus Check auto-exposure with settle-frame skipping, hardware read-back sync, convergence locking (`hdrscan.LiveAE`), and jitter-free status labels.
6. Hikrobot on macOS (unreleased, W7): `hikcam` loads the official MVS SDK for macOS (`MvCameraControl.framework`, arm64 + x86_64) at run time and reports the camera as unavailable without it; tested in CI only against a stub library. Next: with the SDK installed on an Apple Silicon Mac, enumerate and capture from the MV-CS240-90UM over USB3 (and a GigE body if available, with Hikrobot's GigEVision Image Filter), time a full-resolution Mono12 grab against Windows, check that the SDK needs no MV_CC_Finalize at exit, and wire the camera into the Mac UI once it exists. Hikrobot's redistribution terms for the framework are not published, so users install MVS themselves.
7. macOS user interface in Gio (unreleased, W9): increment 1 has the window, page bar, theme, Camera and White light scan pages, native file panels, crash log, .app packaging and CI; group (a) adds the Light page (RGB Light Air, auto film-base leveling, presets); group (b) adds Crop & Merge (Crop, Merge files, Remove hairs, Batch RAW to TIFF); group (c) adds Trichrome and Mono trichrome (Hikrobot through the W7 backend); group (d) adds Focus check; group (f), slice 1 adds Chart calibration and the Camera page's leveling metadata switch. Convert is not part of the macOS app, by the user's decision (the Windows app keeps it): the Mac page bar has three modules and no "Open in Develop", "Send base to Develop" or "Send to Develop" button. Known follow-ups that would change the Windows exe are listed in MAC_UI.md. Next: the film-base DB tools (Record base, Save base to DB, Save last frame 0 to DB, Manage) and the Fixed frame 0 film-stock comparison (group f, slice 2). Check the live view and capture on a real Apple Silicon Mac, including a Mono trichrome capture, Focus check and a Chart calibration of a real chart scan with the MVS SDK installed and the RGB Light Air. See [MAC_UI.md](MAC_UI.md).

DCTL export is retired, not planned work. Historical implementations remain in tags through v0.90. Resolve GPU rendering, viewer picking, and per-stock Base presets belong to the OFX product.

The root `template.dctl` and `template_core.dctl` remain unchanged as inputs to `ofx/tools/generate.py`. They are not app assets or app export features. Removing them would break OFX regeneration, so app-only cleanup does not delete them.
